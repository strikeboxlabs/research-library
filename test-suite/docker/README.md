# Worker image and isolation

Build this optional, small Ubuntu 24.04 fixture image from `test-suite/`:

```bash
docker build -f docker/Dockerfile -t skillbench-pi:1.3.0 .
```

It includes Pi **1.3.0**, Node **22.23.4**, Python 3, jq, tar, SQLite, ripgrep and fd-find. The Node tag is listed in the [official image manifest](https://github.com/docker-library/official-images/blob/master/library/node). It is a scaffold, not an image containing all research-library tools. Point `runtime.image` at your own controlled toolbox image to test its installed capabilities; that image must provide `python3`, `pi`, `bash`, `rg` and either `fd` or `fdfind` on PATH and writable ephemeral `/home/worker` and `/tmp` mounts. Pi's [1.3.0 tool resolver](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/utils/tools-manager.ts) accepts Ubuntu's `fdfind` directly; no alias is needed. Its `grep` and `find` tools need ripgrep and fd even though the shell also supplies GNU grep/find. The controller records the locally resolved image ID and should use that ID for every comparison. Base tags and apt repositories can move, so rebuilding this Dockerfile alone does not reproduce an earlier image.

The runtime uses Docker only. It mounts a disposable fixture at `/workspace` read-write and a selected package snapshot at `/skills` read-only. It never mounts the suite, evaluator answers, the repository root or the Docker socket. Callers must stage those two directories correctly; they must not put answer keys in a fixture. The default numeric identity is the invoking user's nonroot UID/GID. A root controller must explicitly configure an unprivileged UID/GID and ensure it can write the fixture directory. Docker Desktop callers can specify a UID/GID suitable for their Linux image.

The container has a read-only root filesystem, bounded memory, CPUs and PIDs, dropped capabilities, no privilege escalation, ephemeral home/tmp filesystems and an owned unique container name. Timeout and output-limit handling kill and remove that container, including its children. The container name is saved atomically to `runtime.json` before launch; crash recovery cleans only that saved owned name. Cleanup failures are reported with `cleanup_confirmed: false`: do not grade or reuse a workspace while its worker may still be running. Wall time excludes neither shutdown nor cleanup; termination adds up to bounded cleanup/client waits to the configured worker deadline. These controls suit the included file/data tasks. Kernel tracing, privileged administration, multi-host services and other special environments need separately designed fixtures; the mere presence of their binaries does not make those tasks testable.

`network` defaults to Docker's `bridge` so the model API is reachable. This is **not an egress allowlist**. Use a dedicated restricted Docker network/proxy when target boundaries require one. Host networking and shared-container networking are rejected. The API credential is inherited only by its configured environment-variable name (`api_key_env`, default `ZAI_API_KEY`); its value is not included in the Docker command or persisted in a provider file. The worker can inspect its environment, so use a dedicated bounded test credential and keep raw transcripts private. Do not put secrets in task prompts, configuration JSON or images.

The worker starts Pi with explicit provider/model, JSON print mode, no persisted session and automatic skills, extensions, MCP, templates and context files disabled. Only the selected `/skills/<name>` paths are advertised. Retries, compaction, analytics and cache warming are disabled in ephemeral settings for these short controlled trials. Configuration can provide `base_url` (and optionally `api`, default `openai-completions`) to define the exact model even when it is absent from Pi's bundled catalogue. The generated `models.json` contains an environment-variable reference, not the key. Custom model defaults are 131072 context tokens, 8192 maximum output tokens, reasoning enabled and medium thinking; override `context_window`, `max_tokens`, `reasoning` and `thinking` with verified facts. `temperature` and `top_p` are optional, explicit custom-model sampling settings. Record them rather than assuming provider determinism.

Pi's `--offline`/`PI_OFFLINE=1` disables automatic management networking, including catalogue refreshes and missing helper downloads; it does not disable the requested model inference. [Pi's environment reference](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/environment-variables.md) defines this scope. Docker networking controls remain separate. Preflight checks the grep/find helper prerequisites so missing offline helpers cannot silently change the available worker tools.

`preflight(config)` checks Linux Docker availability, local image ID, required executable names and the pinned Pi version/help with networking disabled. It does not call the model API, prove authentication, verify the full tool procedures or test fixtures. `run_worker(...)` records capped JSONL/stdout and stderr separately; a process exit is not task success. The outside evaluator determines correctness.

`run_reference(workspace, script, config, log_dir)` uses the same container and cleanup bounds to execute an evaluator-authored Bash reference with networking disabled, only the disposable workspace mounted, and no API credential forwarded. Its model usage is known zero. The outside grader must still check the resulting artifacts. Both the wall-time limit and Pi's `length` stop are failed worker trials. Exit 137 is recorded as a killed-worker budget failure without claiming that it proves OOM specifically.

Token metrics use finalized assistant messages, with older turn/agent event fallbacks, and avoid counting streamed copies repeatedly. Missing or all-zero usage stays unknown; zero-dollar model metadata is not treated as evidence of free requests. Recorded costs are Pi estimates, not reconciled invoices. Skill-read counts observe the built-in `read` tool's absolute `/skills/...` paths; shell reads, relative aliases and comprehension are not established. `tool_calls` counts observable calls, not shell subprocesses. The raw event files retain evidence for deeper analysis. Limits cover combined retained stdout/stderr; overflowing output is `budget_exceeded`, which counts as a failed worker trial rather than being excluded as infrastructure failure.

The launch flags and environment interpolation were checked against Pi's tagged [1.3.0 CLI source](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/cli/args.ts), [model configuration](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/models.md) and [configuration-value resolver](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/resolve-config-value.ts). Current [event-stream documentation](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/json.md) distinguishes low-level `agent_end` from final `agent_settled`; the one-shot runner waits for process exit. Unit tests mock Docker and model events. Building this image and executing real Linux/Pi/model fixtures require a Docker-enabled Linux deployment and are not implied by those tests.

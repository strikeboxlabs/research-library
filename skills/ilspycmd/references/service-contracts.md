# Trace acquired managed-service contracts

Use the entrypoint's class inventory, selected-type decompilation and matching-reference directory. Preserve acquired client, service, contract assemblies and configuration association; an adjacent source project may differ from the deployed assembly. If only original source is available, inspect it directly rather than inventing decompilation output. Missing service implementation or config leaves the corresponding conclusion unresolved.

Select the host/start method, declared endpoint contract and necessary implementation. Export them through the existing `-t` procedure, or use the fresh `-p -o` project view when declarations span files. Follow the actual channel/endpoint registration and selected operation; keep reconstructed expressions separate from observed deployment.

For async methods, resolve the compiler-generated state machine and its `MoveNext` body, using IL when reconstruction is incomplete. A delay field, method name or role table cannot establish the missing loop, dispatch comparison or exception handling. One registered hosted worker does not prove that constructors, callbacks or dependencies have no other behavior. Mark reconstructed pseudocode as a hypothesis until the body supports it.

For .NET Framework Remoting, distinguish the channel's port/address/remote-request settings, formatter and TypeFilterLevel, authentication/transport-security inputs and registered type/object URI/lifetime. An acquired client endpoint using localhost names that client's loopback, not a globally reachable service. Full permits all types supported by remoting in its situations; Low is not a security guarantee for untrusted BinaryFormatter data. A numeric enum, port scanner label or hardcoded client credential does not prove deployed server policy, authentication or execution identity. Retain secrets only as redacted exposure findings. See [TypeFilterLevel meaning](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.serialization.formatters.typefilterlevel).

For WCF, pair endpoint binding/address/contract with effective configuration and its selected security mode. Transport Windows authentication and encryption/signing protect the channel; they do not decide each operation's authorization or service process identity. Message credential properties are not a second active message-security layer when only Transport mode is selected. See [Windows transport security](https://learn.microsoft.com/en-us/dotnet/framework/wcf/feature-details/transport-security-with-windows-authentication).

For named pipes, distinguish connection DACL, application authentication, operation authorization and service execution identity. Trace the actual deserializer as well as the serializer: emitted field layout does not establish received-length checks, limits, signature verification or replay handling. A byte-mode stream can return fewer bytes than requested even into a large buffer; compare the returned count with each parsed field and declared length. See [Stream.Read semantics](https://learn.microsoft.com/en-us/dotnet/api/system.io.stream.read). Keep static findings separate from constructing a client or replaying captured keys.

For typed deserialization, follow the selected resolver, allowed types and property setters. A runtime configuration naming a shared framework is not proof that every type is loaded or permitted. `Type.GetType` resolution depends on the supplied name, assembly qualification and load context; a null result differs from safe acceptance. Recommend explicit permitted types and schema validation from this evidence, without generating a serialized execution chain. See [type resolution](https://learn.microsoft.com/en-us/dotnet/api/system.type.gettype).

Trace the operation contract and body separately. Default OperationContract is request-reply even for void methods; an endpoint is not inherently asynchronous. IsOneWay, async call patterns and queueing need their own evidence. A body accepting text and passing it to a scripting engine has code-execution semantics, unlike an ordinary data query. Identify that flow statically without generating serialized objects or invoking it. Return values can omit error streams or catch failures; lack of output is not proof of no side effects. See [request-reply and one-way semantics](https://learn.microsoft.com/en-us/dotnet/framework/wcf/feature-details/one-way-services).

Finish with the acquired endpoint/contract/operation/guard flow and missing deployment or identity evidence. A client process's local identity, network credential and returned server-side identity are different observations. Windows netonly credentials select remote access while retaining the caller's local context; a newly opened window alone validates neither account nor server privilege. Preserve a failed transport operation separately from authentication hypotheses. See [runas network-only semantics](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/cc771525(v=ws.11)).

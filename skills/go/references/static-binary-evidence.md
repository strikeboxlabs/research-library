# Inspect a selected Go binary without running it

Use an owned artifact and a fresh evidence file. Establish the artifact's identity separately, then define `artifact` as its explicit path:

~~~bash
GOTOOLCHAIN=local go version -m "$artifact"
~~~

Check the command's exit status. The command inspects embedded Go build information; it does not launch the artifact. Available module/build fields depend on the binary and toolchain. Missing or unrecognized metadata does not establish the language, provenance or safety of the file. Preserve any reported compiler version and module revisions before comparing API behavior. See [go version](https://pkg.go.dev/cmd/go#hdr-Print_Go_version).

Treat decompiler names and reconstructed expressions as leads. Trace the selected function's callers, argument types, branches, error handling and actual launch methods. A configuration loader or `os.Getenv` reference does not prove a configuration file was found or accepted. A `net user` string does not establish that a child process ran. Use the command-construction guidance in the entrypoint to distinguish those outcomes.

## Interpret randomness and decoding evidence

Distinguish package-level `math/rand.Seed` from a particular `(*rand.Rand).Seed` call. Package-level seeding changed with Go 1.20 and became a no-op by default in Go 1.24; that fact does not describe every instance method or an older binary. Match the observed API and compiled toolchain before interpreting the sequence. `Intn(n)` returns values in `[0,n)`; account for any subsequent offset, conversion, earlier calls and concurrent consumers. A seed alone does not establish the generated bytes. `math/rand` is unsuitable for security-sensitive randomness. See the [API and version notes](https://pkg.go.dev/math/rand).

Check the exact Base64 alphabet, padding contract and decoder error before treating bytes as complete. URL-safe encoding uses a different alphabet from standard Base64. Ignoring a conversion or decoding error can carry a default or partial result into later processing.

An encryption mode and ciphertext are different evidence from a password digest. In particular, [CFB decryption](https://pkg.go.dev/crypto/cipher#NewCFBDecrypter) does not authenticate its result: readable output alone establishes neither integrity nor correct provenance. Preserve configuration, generation timing and parser uncertainties rather than turning a reconstructed decoder into a claim that a live account or service accepted the value.

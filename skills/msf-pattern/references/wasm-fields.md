# Measure a browser display-field overwrite

Use this when a controlled application's user-controlled field passes through an Emscripten/WebAssembly display function and appears in another rendered field. Preserve the raw API record, exact submitted bytes, JavaScript argument order, paused memory values and resulting DOM. This is a data-flow/layout measurement; it is not proof of a native saved-return-address overwrite or OS execution.

## Locate the boundary

Inspect the actual loader rather than inferring a display path from the editor. For **illustrative glue**, `Module.ccall("display", "number", ["string","string"], [created,author])` converts those strings for the compiled call. Pause inside the exported function and examine the two pointer arguments. If the build exposes `UTF8ToString`, decode the observed pointer with a suitable byte bound while paused:

~~~javascript
UTF8ToString(observedPointer, 256)
~~~

Use an actual pointer in the current heap, not one copied from a walkthrough. Emscripten ccall string arguments use temporary stack storage; their lifetime ends with the call. UTF-8 byte length, a NUL terminator and allocation/alignment matter. A difference between two pointer values is a layout clue; it is not enough to establish the vulnerable copy's length. A missing exported runtime function or optimized/debug-variable name calls for examining that build's glue, not assuming the application has no string buffer.

Observe whether the original field is escaped at its DOM sink and whether a different field is handled differently. A client HTML `maxlength` is separate from server-side validation. In the controlled request, replace the selected user field with a bounded ASCII pattern generated by the existing Metasploit helper:

~~~bash
"$pattern_create" -l "$length" >"$pattern_file"
~~~

Remove only the generator's final line terminator when the application field must not contain it. Preserve the actual sent value, including any form/JSON decoding. Use the application's observed registration/update endpoint and current CSRF/session context; changing the DOM limit without changing the transmitted bytes is not the same test.

When a fragment lands in the adjacent field, use the entrypoint's matching pattern_offset invocation with the same length/sets. A longer observed fragment can be compared to the saved exact ASCII bytes with a standard byte-search helper, retaining all occurrences rather than silently choosing the first. HTML escaping, truncation, percent decoding or UTF-8 conversion can make a DOM substring differ from memory. An **illustrative offset 48** means that field begins at byte 48 in that specific input path, not that all builds use 48.

## Confirm rendering and choose the next action

Repeat with a short distinctive marker at the measured boundary. Compare raw record, paused memory and DOM to establish where transformation occurs. Only after that, if browser-execution testing is authorized, use a minimal visible browser marker such as an event handler printing a unique public token. Distinguish inserted text, parsed HTML, event execution, an outbound resource request and execution of an externally loaded module.

An escaped username can still become unsafe when corrupted data reaches a date field with a different HTML sink. The WebAssembly memory boundary and HTML escaping boundary are two separate defects; neither alludes to escaping the browser sandbox. A callback received after a report/review action can show that another renderer visited the stored record, but peer IP or headless user-agent alone does not establish administrator identity. Use the selected session's actual accessible response/action to substantiate that conclusion.

If an external JavaScript module is used, verify its response MIME type and CORS policy in the browser; a raw TCP listener can capture a GET without supplying any valid module response. HttpOnly restricts direct cookie reading but does not prevent script executing in the application origin from making session-bound requests. Those follow-on application actions need their own route/token/response evidence, not a claim that the cookie was decrypted or stolen.

References: [Emscripten ccall and UTF8ToString](https://emscripten.org/docs/api_reference/preamble.js.html), [cookie attributes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie), and [browser CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS).

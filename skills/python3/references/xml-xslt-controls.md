# Review XML parsing and XSLT transformation separately

Use acquired Python source and deployment configuration; do not import the application or execute an uploaded stylesheet to inspect it. Trace each uploaded file through storage, parser construction, stylesheet compilation, transformation and output handling. Keep the XML document and stylesheet paths separate in the evidence.

A parser passed to `etree.parse(xml_path, parser)` does not automatically become the parser used by a separate `etree.parse(xslt_path)`. Follow the actual objects and any resolver registrations. Settings such as `resolve_entities=False`, `load_dtd=False` and `no_network=True` are not a blanket filesystem policy for every later stage. Inspect stylesheet imports/includes and their resolver context separately from transform-time I/O.

For remediation, prefer application-owned stylesheets. Where an application must accept untrusted transformations, review its explicit `etree.XSLT(..., access_control=etree.XSLTAccessControl.DENY_ALL)` policy: this disables the listed file/network read/write and directory-creation operations during transformation. Individual permissions are independent; denying reads alone does not deny writes. This control does not govern stylesheet parsing/imports, custom extension code or CPU/memory consumption. Restrict resolver behavior and extension registration, keep the process unprivileged and apply independent resource limits. See [I/O and resolver scope](https://lxml.de/resolvers.html#i-o-access-control-in-xslt) and [XSLTAccessControl](https://lxml.de/apidoc/lxml.etree.html#lxml.etree.XSLTAccessControl).

Review output handling as a separate boundary. Writing the returned transformation result to one server-chosen filename does not establish that the transformation had no other effects. Upload filename handling requires the complete [path review](path-handling.md) before making a containment claim. An installation document proposing a periodic job is not evidence that the job is installed; correlate actual scheduling and execution context before attributing downstream behavior.

Finish with the exact parser/transform controls, selected remediation and unresolved deployment facts. A source-level control review is not a successful runtime confinement test; distinguish parsing, compilation, application and output failures when later controlled validation is available.

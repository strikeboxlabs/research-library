# Capture a selected page without assuming a working clone

Use the entrypoint's selected URL/new-output/status/log procedure. `-O`/`--output-document` stores the fetched response bytes under that name; it does not render JavaScript, acquire the browser's session automatically or recursively collect CSS/scripts/images. A redirected login/error response can be a successful transfer of the wrong page. Confirm final URL/content before using it as the owned task's template.

If the task serves a reviewed acquired page on another origin, inspect its form action/method/field names, any `base` element and all needed asset URLs. A relative `/static/site.css` now resolves on the new origin; copying only the HTML commonly produces missing styles or a different form destination. Choose owned local assets or an explicit authorized origin and verify actual browser requests. Remote script inclusion can execute that script in the containing page's origin. Wget's HTTP result does not validate rendering, browser origin controls or authentication.

For a task that explicitly needs one page and its requisites, GNU Wget offers `--page-requisites --convert-links --adjust-extension --directory-prefix`. This makes additional requests and edits saved links; define an owned destination and restrict the requested scope first. Do not add mirroring/recursive options to a one-artifact task merely to fix a missing stylesheet. Cross-host requisites and authenticated/dynamic resources need their actual routing/session policy; `--span-hosts` broadens destinations and is not an automatic default.

Keep original captured bytes separately when transformations matter. An existing `-O` target is truncated immediately, so use a fresh file. Finish with complete transfer and selected-content evidence; a visually matching copied page still proves no submitted credentials, legitimate session or account access. See [GNU Wget requisites and link conversion](https://www.gnu.org/software/wget/manual/wget.html).
